# /git-init — підготовка Git-репозиторію

Дій як агент `build-engineer` (`.claude/agents/build-engineer.md`): дотримуйся
його правил роботи з файлами та заборонених дій.

## Передумови

- Встановлено `git`.
- Поточний каталог — корінь проєкту (або порожній каталог для нового репозиторію).

Перевір передумови лише командами з `allowed-tools`, окремим викликом Bash
(без `&&`, `;`, `|`): `git rev-parse --show-toplevel`. Вивід шляху — git є і
каталог у репозиторії; `fatal: not a git repository` — git є, репозиторій
треба створити (крок 1); `command not found` — `git-init: FAIL — git не
встановлено або недоступний.` Не використовуй `git --version`: його немає в
`allowed-tools`, і headless-запуск його відхиляє.

## Дії

1. Перевір репозиторій: `git rev-parse --is-inside-work-tree`.
   - Не репозиторій → `git init -b develop` (лише якщо каталог не є
     підкаталогом іншого репозиторію).
   - Репозиторій → нічого не ініціалізувати повторно.
2. Покажи поточну гілку: `git branch --show-current`.
3. Створи або онови `.gitignore` за **канонічним списком** зі skill
   `project-scaffold` (розділ «Канонічний .gitignore»):
   - файлу немає → створи його з повним списком (міграція не потрібна);
   - файл є → спершу **міграція** (3а), потім **доповнення** (3б).
     Існуючі рядки не змінюй і не видаляй — за винятком міграції 3а.

   **3а. Міграція застарілих рядків.** Старі версії skill містили шаблони
   без початкового `/`. Такі шаблони діють на будь-якому рівні вкладеності,
   тому, наприклад, `build-*/` ігнорував `.claude/skills/build-and-test/`.
   Для кожної пари з таблиці:

   | Застарілий рядок | Канонічний рядок |
   |------------------|------------------|
   | `build-*/` | `/build-*/` |
   | `cmake-build-*/` | `/cmake-build-*/` |
   | `out/` | `/out/` |
   | `Testing/` | `/Testing/` |

   перевір наявність обох рядків двома окремими викликами:
   `grep -qxF '<застарілий>' .gitignore` і `grep -qxF '<канонічний>' .gitignore`
   (код 0 — рядок є, код 1 — немає). `-x` порівнює рядок цілком, тому
   `grep -qxF 'build-*/'` не спрацює на `cmake-build-*/` чи `/build-*/`.

   | Застарілий | Канонічний | Дія |
   |------------|------------|-----|
   | є | немає | **Edit**: замінити застарілий рядок на канонічний на тому самому місці |
   | є | є | **Edit**: видалити лише застарілий рядок (канонічний уже є — не дублювати) |
   | немає | є / немає | нічого (відсутній канонічний рядок допише крок 3б) |

   Правила Edit для міграції:
   - замінюй **рядок цілком**. `build-*/` — підрядок `cmake-build-*/` і
     `/build-*/`, тому в `old_string` бери рядок разом з сусіднім рядком
     (або символом нового рядка перед ним), щоб збіг був унікальним;
     `replace_all` не використовуй;
   - не чіпай коментарі та інші рядки, не змінюй порядок;
   - після кожної заміни перевір: `grep -c -xF '<канонічний>' .gitignore` → `1`,
     `grep -c -xF '<застарілий>' .gitignore` → `0`.

   **3б. Доповнення.** Для кожного рядка канонічного списку перевір
   `grep -qxF '<рядок>' .gitignore` і допиши лише відсутні рядки.
4. Перевір, що тимчасові каталоги і секрети ігноруються — три окремі виклики,
   кожен має завершитися з кодом 0:
   `git check-ignore -q build/`, `git check-ignore -q dist/`, `git check-ignore -q .env`.
5. Перевір, що файли агента **не** ігноруються — два окремі виклики:
   - `git check-ignore -v --no-index .claude/skills/build-and-test/SKILL.md`
     → порожній вивід і код виходу 1 (код 0 і вивід `.gitignore:N:<шаблон>` = FAIL);
   - `git ls-files -c -i --exclude-standard -- .claude` → порожній вивід
     (немає відстежуваних файлів агента, що збігаються з правилами ігнорування).
6. Перевір, що в індексі немає артефактів: `git ls-files build dist .cache`
   повинно повернути порожній результат.
7. Якщо `.gitignore` змінився (`git status --porcelain .gitignore` не порожній) —
   `git add .gitignore` і коміт:
   - була міграція (3а) → `git commit -m "fix(git): прив'язати build-*/, cmake-build-*/, out/, Testing/ до кореня репозиторію"`;
   - лише доповнення (3б) → `git commit -m "chore(git): .gitignore для build/dist, кешів, IDE та секретів"`.

   Якщо змін немає — коміт не робити.
8. Покажи стан: `git status --short --branch`.

## Очікувані файли

- `.gitignore` з усіма рядками канонічного списку (кожен рівно один раз) і
  без застарілих рядків із таблиці міграції.

## Команди перевірки

Кожна команда — окремий виклик Bash; очікуваний результат після стрілки.

1. `git rev-parse --is-inside-work-tree` → `true`.
2. `git check-ignore -q build/` → код виходу 0.
3. `git check-ignore -q dist/` → код виходу 0.
4. `git ls-files build dist` → порожній вивід.
5. `grep -c -xF 'build/' .gitignore` → `1`.
6. `grep -c -xF '/build-*/' .gitignore` → `1`.
7. `grep -c -xF 'build-*/' .gitignore` → `0` (код виходу 1 — застарілого рядка немає).
8. `git check-ignore -v --no-index .claude/skills/build-and-test/SKILL.md` →
   порожній вивід, код виходу 1.
9. `git ls-files -c -i --exclude-standard -- .claude` → порожній вивід.
10. `git status --short --branch` → поточна гілка, без неочікуваних змін.

## Ідемпотентність

Повторний запуск не створює новий репозиторій, не дублює рядки `.gitignore`
і не створює порожній коміт. Міграція спрацьовує лише один раз: після неї
застарілих рядків немає, тому наступний запуск нічого не змінює.

## Повідомлення про помилку

- `git-init: FAIL — git не встановлено або недоступний.`
- `git-init: FAIL — каталог є підкаталогом іншого репозиторію (<шлях>); ініціалізація скасована.`
- `git-init: FAIL — у Git відстежуються файли з build/ або dist/: <список>. Видаліть їх з індексу вручну (git rm --cached), агент цього не робить.`
- `git-init: FAIL — файли агента ігноруються Git: <вивід git check-ignore -v>. Перевірте рядок .gitignore:<N>; якщо це шаблон не з таблиці міграції — виправте його вручну або додайте в таблицю skill project-scaffold.`

## Формат звіту

```
git-init: OK
Репозиторій: <шлях>, гілка <назва>
.gitignore: створено | додано N рядків, мігровано M рядків | без змін
Перевірки: build/ ignored, dist/ ignored, .claude/ not ignored, tracked artifacts: 0
```
